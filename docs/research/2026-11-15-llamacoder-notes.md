# llamacoder: what is worth taking (2026-11-15)

Source: Nutlope/llamacoder (upstream, active), read from a shallow clone of `main`. Our fork was deleted in the GitHub cleanup; these notes are what we keep.

## What it is
An open "Artifacts" clone: one prompt becomes a React + Tailwind + TypeScript app that is compiled and run in the user's browser and shown in a sandboxed iframe. Next.js app, Prisma/Postgres for chats, S3 for screenshot uploads, Braintrust for traces, one hosted inference provider. Two things changed since its early fame: it is no longer single-file (the prompt now demands 3-5 files, each in a `{path=...}` fence) and it no longer uses Sandpack (`architecture.md` explains the move to its own renderer). The value is in the renderer, the error-to-fix loop and the benchmark harness, not the chat UI.

## 1. In-browser bundler: esbuild-wasm over a virtual filesystem
`lib/preview/bundle.ts`: `esbuild.initialize({ wasmURL })` once (promise cached on `globalThis`), then `esbuild.build({ entryPoints:["/main.tsx"], bundle:true, write:false, format:"esm", target:"es2022", jsx:"automatic", define:{"process.env.NODE_ENV":"\"production\""} })` with one plugin. The plugin's `onResolve` maps relative/`@/` paths into a `vfs` namespace backed by the generated files plus injected UI-kit files (`lib/preview/files.ts`), marks bare specifiers `external`, and returns a resolve error for anything else; `onLoad` picks the loader by extension. Bundles are cached by a content key (`cache-policy.ts`). Errors are reformatted so the `vfs:` prefix does not confuse the model (`formatEsbuildError`).
**For us:** this is the cheapest way for Moon to run code a peer or its own small model writes: no server, no Node, just a wasm bundler and a file map. It also suits SKIBIDI's "Functions (Edge) = WASM execution" row: an app delivered as signed source records, bundled on the receiving peer.

## 2. Pinned dependency allowlist via import map, esm.sh as fallback
`lib/preview/deps.ts` / `html.ts`: externals resolve through an `<script type="importmap">` built from one pinned version table (`PREVIEW_DEPS`). Hot packages (React, UI kit, Tailwind browser build) are prebuilt and self-hosted under `/public/preview-vendor-v2`; the rest go to `https://esm.sh/<pkg>@<ver>?bundle&external=react,react-dom` (`?bundle` collapses deep graphs like framer-motion's ~90 modules into one request; `external=react` prevents duplicate Reacts). `modulepreload` links are emitted from a precomputed vendor graph. Before boot, `findMissingPreviewModules` scans the bundle for bare imports the map cannot resolve and fails fast with a fixable message, because an unresolvable import kills a module script silently.
**For us:** the version table is the allowlist; prompt, policy check and import map are all generated from it so they cannot drift. For Moon/SKIBIDI, replace esm.sh with content-addressed modules fetched from peers (hash in the import map), so a delivered app runs offline and cannot be swapped under it.

## 3. Sandbox and its limits
`components/code-runner-react.tsx`: `<iframe sandbox="allow-scripts allow-forms" srcDoc=...>`; no `allow-same-origin`, so the app runs at an opaque origin with no access to the host's cookies, storage or DOM, and no top navigation or popups. Host accepts messages only when `event.source === iframe.contentWindow && data.source === "preview"`. **Limits:** no CSP at all (grep finds none), so generated code can `fetch` any URL and load any script; child posts with `targetOrigin "*"`; the user can still be phished inside the frame; resource exhaustion is only bounded by a watchdog that marks the run failed, not by killing the frame.
**For us:** Moon must add what is missing before running peer-supplied code: a `<meta http-equiv="Content-Security-Policy">` in the srcdoc restricting `script-src` to the import map's hashes and `connect-src` to none (or the SKIBIDI bridge), and a capability bridge over `postMessage` instead of network access. Opaque origin is also why the app cannot reach Moon's IndexedDB keys; keep it that way.

## 4. Error bridge and one-shot auto-fix
`lib/preview/html.ts` injects a bootstrap that posts `error` (window `error`, `unhandledrejection`, module script `onerror`), `console-error` (wrapped `console.error`), `document-loaded`, `tailwind-ready` and `ready` with timings. The host keeps a state machine (bundling → running → ready/error) plus a watchdog (`PREVIEW_WATCHDOG_MS`); watchdog failures set `canAutoFix:false`. An error is formatted with preceding console errors (`formatErrorForFixPayload`) and sent as a user message prefixed `FIX_REQUEST_PREFIX`. `lib/chat-auto-fix.ts` allows exactly one automatic fix per generation: not while streaming, only for the latest file-bearing reply, never if the prior user turn was already a fix (manual "Try to fix" remains). `describePathlessFenceProblem` replaces a misleading symptom ("Cannot resolve @/lib/data") with the real cause (fences lacking `{path=}`), after a model resent byte-identical code twice.
**For us:** Trailblazer's verify step should copy two rules: a bounded repair budget per artifact keyed by content hash (`autoFixSentForFilesRef`), and diagnosis rewriting, i.e. detect known output-shape failures and tell the model the cause, not the downstream error. Frontier: "no ready signal" (timeout) is not a fixable error and should go to the workspace, not back to the coder.

## 5. Output contract and prompt engineering
`lib/prompts.ts`, `lib/prompt-config.ts`: files as fenced blocks ```` ```tsx{path=src/App.tsx} ````; "only output changed files in iterations"; library list and UI-kit component docs generated from the dep table; hard bans (no arbitrary Tailwind values, no gradients, no axios/router). A separate planning call ("software architect") was benchmarked and dropped for an inline instruction ("plan internally, emit only code"). A final self-check about fence format is appended last because models ignored the same rule mid-prompt. The parser (`lib/utils.ts`) normalizes fence openers, strips thinking blocks and dedupes fallback filenames so pathless fences do not collapse into one file.
**For us:** confirms our raw-text-tag rule for local models: code goes in path-tagged fences, never JSON. "Critical rule repeated last" is a cheap Trailblazer prompt fix. Edits are whole-file replacements merged by path; simple and robust for small models.

## 6. Edit loop and context budget
`app/api/get-next-completion-stream-promise/route.ts`: whole history is resent, but code fences are stripped from all assistant turns except the last two (`[code omitted]`), and long chats keep the first three messages plus the last seven. `max_tokens` 20000 as a cap, with a 270 s supervisor (`lib/completion-stream-lifecycle.ts`) so completed files survive a deadline. Stored model ids pass an allowlist with an alias table for retired models (`lib/constants.ts`).
**For us:** the strip-old-code rule is a direct Trailblazer/planner context saving: only the latest file state matters, earlier versions are noise. The alias table is how planner should map retired model ids in old cards.

## 7. Screenshot to app
`app/api/create-chat/route.ts`: a vision model turns the image into a <=180-word layout description (`screenshotToCodePrompt`), appended to the prompt as "RECREATE THIS APP AS CLOSELY AS POSSIBLE"; the coder never sees pixels. Failure degrades to text-only.
**For us:** perception-to-text before the coder is the Frontier pattern (senses feed the workspace as descriptions). Cheap; a small vision model suffices.

## 8. Benchmark harness: mechanical gate, then screenshot judge
`scripts/benchmark/`: prompts carry `expectedBehavior` lists (`prompts.json`). `eval-runner.ts` renders each output in Playwright through the same preview pipeline; `policy.ts` statically flags forbidden imports, subpath imports and arbitrary Tailwind utilities; only a mechanical pass (build ok, runtime ok, screenshot taken) goes to `judge.ts`, a vision judge scoring per-behavior met/not-met/cannot-tell plus 0-10 with anchors ("beautiful but incomplete <= 6", "error/blank 0-2"). Prompt variants (`minimal-v1`..`v11`) are applied as checked string patches that throw if the base template drifted. Production config is "the locked winner" of a dated campaign.
**For us:** the strongest takeaway for Trailblazer and the SWE-bench lab: gate cheap mechanical checks before any model judge, judge against an explicit behavior checklist, and keep production prompts byte-identical to benchmarked ones (shared constants). The runner exposes timings as `data-preview-*` attributes, which makes Playwright assertions trivial.

## Not worth taking
Next.js/Vercel shell, Prisma/Neon, S3 upload flow, rate limiting, share/OG pages, Braintrust coupling (spans per LLM call are fine; any tracer works), the prescriptive design-aesthetic prompt text, the shadcn/Base UI kit itself, and esm.sh as a runtime dependency.
